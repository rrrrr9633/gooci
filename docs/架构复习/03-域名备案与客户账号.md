## 别人家（iSESOL）域名是怎么配的

截图事实：

```text
isesol.com        门户 + 工作台聚合（官网导航和工作台混在一起）
e1.isesol.com     「设备云眼」独立产品站
app.isesol.com    应用商城
```

点「设备云眼」会离开门户主机名，进子域名。这是 **门户 + 产品子域名**，不是一台机一个路径。

更像多客户共用的 SaaS 产品集群，**不是**「一家客户一台机、所有模块挂在同一路径」。  
不要学子域名矩阵。

## 一个域名能解析几个 IP、几台云服务器

- 一个主机名可以挂很多条 A 记录，协议没有「最多 2 个 IP」。
- **多 IP ≠ 按客户选机器。** DNS 只会轮询/随便给一个 IP，不认登录账号。
- 同一名字一般不能既做 CNAME 又做 A。

正确三层：

```text
域名
  → 解析出 1～N 个 IP（用户只看到这层）
      → IP 后面可以是一台云服务器
        或一台入口/负载均衡，后面再挂很多云服务器
```

| 用法 | 行不行 |
|---|---|
| 一域名 → 一个 IP → 一台机 | 开张可以 |
| 一域名 → 多个公网 IP 轮询多台客户机 | **不行**，客户会串 |
| 一域名 → 一两个入口 IP → 入口再转到很多机 | **正路** |

**域名解析条数不必等于云服务器台数。**  
公用域名只指向入口；后面机器用内网，不必写进域名。

## 很多客户，不想每家买域名、备案、服务器

### 对外卖什么

客户拿到：账号 + 开通了哪些模块。  
客户打开：你们已经备案好的 **同一个网址**。  
客户没有：自己的域名、自己的备案、自己的云账号。

你们只做一次：1 个域名、备案 1 次、先买少量云服务器。

```text
https://www.goci.com/工作台
登录 A 厂 → 只看到 A 的数据
登录 B 厂 → 还是这个网址，数据另一套
```

不能联网：装 EXE，本机打开，连域名都不用。

### 默认不要「一号一机」

默认隔离靠 **账号 + 客户 ID**，不靠一人一台机、一人一个域名。

一人一台机只留给：断网本地，或愿意加钱独占的大客户。

子域名（`a厂.goci.com`）也不当默认，多一层管理。默认就一个网址，靠登录区分。

客户想用自己公司域名访问：那才要客户自己备案，当定制，默认不提供。
