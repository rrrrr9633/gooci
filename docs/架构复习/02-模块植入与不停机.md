# 02 模块植入与不停机

[← 目录](README.md)

## 客户永远只看到一个域名、一条路径

```text
https://www.goci.com/                 官网（独立，进工作台后不再出现营销页）
https://www.goci.com/工作台/          控制台壳
https://www.goci.com/工作台/轻工单
https://www.goci.com/工作台/设备维保
```

不是 20 个模块 20 个域名。  
不是 `e1.isesol.com` 这种子域名产品站。

## 旁挂 vs 并入（由能不能停机决定）

```text
不能停机  → 模块先单独起后端（旁挂）
            网关把 /工作台/模块名 转到这份进程
            客户路径不变

能停机    → 模块真正并入主后端
            路径仍是 /工作台/模块名
            少一个进程
```

旁挂是过渡，能合并就合并。

控制台记的是绑定，不是另一套网址：

```text
Route = {
  path: "/工作台/轻工单",
  mode: sidecar | merged,    // 旁挂 | 已并入
  target: "允许名单内的公网 https",
  pluginId, version
}
```

可见模块 = 已植入 ∩ 许可有效 ∩ 已启用。

## 旁挂就能不停机吗？

**不完全是。** 旁挂只保证：主后端不用重启，旧模块还能用。

不停机还要同时满足：

1. 控制台菜单运行时拉取，不是打包死在页面里
2. 网关能热加载路由（reload，不是重启整机）
3. 新模块只建自己的表，不改内核表、不锁共享表
4. 不要求先升级内核、不改登录/权限协议
5. 先探活成功再挂路径；失败就摘掉，等于没接入

会破功的：改用户/权限表结构、内核太老必须先升、菜单写死在前端包、网关只能重启、新模块要改已有流程。

作业顺序：

```text
拉起模块进程（此时还没有路径）
  → 跑只属于它的库表
  → 探活成功
  → 热挂 /工作台/模块名
  → 刷新后菜单出现
```

| 动作 | 停不停机 |
|---|---|
| 旁挂接入新模块 | 满足上面 5 条时不停 |
| 并入主后端 | 要停机窗口 |
| 扩容换机 | 旁路切入口，另一套不停机 |

内核如果没有「动态菜单 + 热加载路由 + 模块私有表」，旁挂只是多起了个进程。

## 测试环境怎么展示跳转（不另开公网域名）

域名 A 记录只指向门口。不要给模块再写一条 A 记录。

```text
客户点击工业 APP 砖块
  → /workbench/ext/{appCode}     工作台壳（登录后，客户只看到这一条路径）
  → 同域 /ext/{appCode}/**       门口入口
  → TARGET_URL 必须是允许名单内的公网 https，门口再转到其他云服务器
  → 本机回环、内网地址、未进允许名单：拒绝转发
  → 未绑定：提示未跳到，不再起本机测试进程
浏览器从不打开模块端口，也不写第二条公网 A 记录。
```

## 生产环境：控制台怎么知道这家公司加了模块

模块进程自己不上报、不回调。多客户共用你们的门口，靠企业 ID + 开通表隔离，不按客户搭 VPC。

厂商作业顺序：

```text
拉起模块进程（此时客户还看不见；模块安全组只放行门口）
  → 跑只属于它的库表
  → 把模块主机写入门口允许名单
  → 调 POST /api/ops/apps/implant
       enterId / appCode / appName
       TARGET_URL = 门口能访问的公网 https（如 https://mod-a.example.com）
  → 控制台写 TM_APP_OPEN
  → 客户刷新后工业 APP 出现砖块
  → 浏览器仍只走同域 /ext/{appCode}，由门口转到 TARGET_URL
```

探活是控制台 JVM 去连 TARGET_URL，不是浏览器、也不是 DNS 之外的旁路。  
公网必须 https，主机在允许名单内，且解析结果不能是回环或内网。未达通常是模块没起来、证书/端口不对、安全组没放行门口、或下一跳不在名单里。

运营台改已有模块的隐藏和目标用 `POST /api/ops/apps`，新增才用 implant。

网关只改 HTML 的 src/href、CSS url、以及 JS 里的静态资源根（`/assets/` `/src/` 等）。**不改** JS 里的 `'/'`、路由 path。接口请求靠注入的 fetch 钩子转到 `/ext/{appCode}`。改写过猛会导致模块白屏或按钮失效，不是必然。

工作台的模块砖块均在新标签页打开公网入口，使用 `/ext/{appCode}/` 区分模块，不再嵌入 iframe。AI 功能砖块打开 AI 中台独立页并附带 `fn` 功能编码。

现在控制台和 deepseek-harness 部署在同一台云服务器。harness 只监听 `127.0.0.1:3080`，以 `dsh web --host 127.0.0.1 --port 3080 --no-open --trusted-host <AI公网IP[:端口]>` 启动；nginx 在公网 TLS 端口整站反代到该端口。`GOOCI_AI_HUB_PUBLIC_URL` 配置为 `https://<AI公网IP>:<公网TLS端口>/?token=...`，使用 harness 启动输出的 token；TLS 证书必须包含公网 IP 的 IP SAN。`GOOCI_AI_HUB_LOCAL_FORWARD=true` 只供门口探活访问回环，不是浏览器入口。以后 harness 迁到其他云后，关闭此开关并使用允许名单内的公网 HTTPS 下一跳。
