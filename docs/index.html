接口文档

版本与代码同步：gooci-console 0.1.0。当前后端只实现下列接口，本文按实现逐字段列出。未实现的能力在文末「明确没有」一节，避免误用。

机器可读副本：同目录 openapi.yaml。

1. 基址

场景基址
生产网关https://$GOOCI_PUBLIC_DOMAIN（暂定 https://goocidata.top），路径以 /api 开头
Content-Type请求体 JSON 用 application/json;charset=UTF-8
字符集UTF-8
时区Asia/Shanghai

前端 axios：baseURL=/api，超时 15000ms。下文路径一律写完整 /api/...。

2. 统一信封 ApiResult

所有业务接口（含失败）的 JSON 外壳：

字段类型说明
codenumber0 成功；1 失败
messagestring成功固定 "ok"；失败为原因文案
dataobject / null成功为业务体；失败为 null 或不出现

成功 HTTP 状态码为 200。业务失败（校验、账号密码错误等）也是 HTTP 200 + code=1，不要只看 HTTP 状态。

未登录访问受保护接口：HTTP 401，body 仍是信封：

{ "code": 1, "message": "未登录或登录已过期", "data": null }

3. 鉴权

项约定
算法JWT，HMAC-SHA，密钥 gooci.jwt-secret
有效期12 小时（gooci.jwt-expire-hours）
传递请求头 Authorization: Bearer <token>
无刷新令牌token 过期必须重新登录
无服务端登出前端清 localStorage.gooci-token 即退出

匿名可访问：

  • OPTIONS /**
  • POST /api/auth/login
  • POST /api/auth/sms
  • POST /api/auth/register
  • GET /api/site/meta
  • POST /api/ops/auth/login

其余 /api/** 必须带有效 Bearer。非法/过期 token 视为未登录，返回 401。

企业 token（无 scope 或 scope=enter）不能调 /api/ops/。厂商 token（scope=ops）不能调 /api/console/。厂商退出清 localStorage.gooci-ops-token。

跨域允许来源由 GOOCI_CORS_ORIGINS 注入；方法 GET/POST/PUT/DELETE/OPTIONS；允许携带 Cookie 头。同域部署时不依赖 CORS。

5. GET /api/site/meta

官网公开信息。不登录可调。工作台也会调一次，用于顶栏电话。

请求：无 Query、无 Body。

成功 data

字段类型必有说明
brandNamestring是固定 "GOOCI 谷器"

GET /api/site/meta
{
  "code": 0,
  "message": "ok",
  "data": {
    "brandName": "GOOCI 谷器",
    "servicePhone": ""
  }

6.1 POST /api/auth/sms

演示环境不接短信通道。成功时 data.demoCode 为 6 位数字，前端提示用。5 分钟有效，校验通过后在注册成功时作废。

请求体 SmsCodeCommand：mobile 非空，需匹配 1 + 10 位数字，否则 请填写正确的手机号。

6.2 POST /api/auth/register

成功 data 同登录 SessionView（含 token）。registerKind：ENTERPRISE / PERSON。

请求体 RegisterCommand

字段类型说明
registerKindstringENTERPRISE 或 PERSON
mobilestring登录名=手机号
smsCodestring须匹配未过期验证码
displayNamestring姓名
loginPasswordstring至少 6 位
confirmPasswordstring须与密码一致
enterNamestring企业注册必填，公司名称
jobNamestring个人注册必填，职能
inviteCodestring可空。个人填写时须等于某企业 ENTER_CODE（演示工厂为 DEMO）
agreedboolean须为 true

企业注册：新建企业（certStatus=0）+ 默认部门 + 企业管理员。个人带有效邀请码：加入该企业为员工。个人无邀请码：以姓名新建企业并成为管理员。

失败文案：请阅读并同意平台协议、请填写正确的手机号、验证码错误或已过期、密码至少6位、两次输入的密码不一致、该手机号已注册、公司名称不能为空、请选择职能、邀请码无效、注册类型不正确。

7. GET /api/console/session

取当前登录用户。Header 必须带 Bearer。

与登录的差别

  • 不返回 token（JSON 里为 null 或不使用该值）
  • 其余字段与登录成功体相同（含 menus、脱敏手机号、客服电话）

失败

HTTPcodemessage条件
4011未登录或登录已过期无 Header、token 非法或过期（过滤器拦截，进不了 Controller）
2001未登录理论上 Holder 为空（正常会被 401 拦住）
2001用户不存在token 里的 userId 在库中已删

8. GET /api/console/overview

工作台首页数字。未读条数、待办条数按当前登录人统计。设备数量仍为 0。不做授权码。不做小程序自动传站内信。

成功 data：ConsoleOverview

字段类型当前值前端位置
unreadMessageCountnumber当前用户未读站内信条数工作台右侧「未读信息」
pendingTaskCountnumber当前用户未处理待办条数工作台右侧「待办任务」
linkedDeviceCountnumber0右侧「已接入设备数量」
onlineDeviceCountnumber0右侧「在线设备数量」
recentMessagesarray最多 8 条未读站内信 {id, content}右侧「消息动态」滚动

无 Query。鉴权失败同 session，HTTP 401。

9. 个人信息

工作台「个人信息」页。本页手机号返回库内明文，不做脱敏（与登录 / session 不同）。邮箱未填时 mailAddr 为空串，前端显示「请添加邮箱」。角色、部门、公司、已开通应用只读。角色后「管理」跳 /workbench/org/structure；部门后「管理」跳 /workbench/org/dept。

已开通应用不是控制台菜单模块，只是授权行。演示环境写 2 条，不预装产品目录里的 20 个模块。

02 模块植入与不停机

← 目录

客户永远只看到一个域名、一条路径

https://www.goci.com/                 官网（独立，进工作台后不再出现营销页）
https://www.goci.com/工作台/          控制台壳
https://www.goci.com/工作台/轻工单
https://www.goci.com/工作台/设备维保

不是 20 个模块 20 个域名。

不是 e1.isesol.com 这种子域名产品站。

旁挂 vs 并入（由能不能停机决定）

不能停机  → 模块先单独起后端（旁挂）
            网关把 /工作台/模块名 转到这份进程
            客户路径不变

能停机    → 模块真正并入主后端
            路径仍是 /工作台/模块名
            少一个进程

旁挂是过渡，能合并就合并。

控制台记的是绑定，不是另一套网址：

Route = {
  path: "/工作台/轻工单",
  mode: sidecar | merged,    // 旁挂 | 已并入
  target: "主后端" | "本机:端口",
  pluginId, version
}

可见模块 = 已植入 ∩ 许可有效 ∩ 已启用。

旁挂就能不停机吗？

不完全是。 旁挂只保证：主后端不用重启，旧模块还能用。

不停机还要同时满足：

  1. 控制台菜单运行时拉取，不是打包死在页面里
  2. 网关能热加载路由（reload，不是重启整机）
  3. 新模块只建自己的表，不改内核表、不锁共享表
  4. 不要求先升级内核、不改登录/权限协议
  5. 先探活成功再挂路径；失败就摘掉，等于没接入

会破功的：改用户/权限表结构、内核太老必须先升、菜单写死在前端包、网关只能重启、新模块要改已有流程。

作业顺序：

拉起模块进程（此时还没有路径）
  → 跑只属于它的库表
  → 探活成功
  → 热挂 /工作台/模块名
  → 刷新后菜单出现
动作停不停机
旁挂接入新模块满足上面 5 条时不停
并入主后端要停机窗口
扩容换机旁路切入口，另一套不停机

内核如果没有「动态菜单 + 热加载路由 + 模块私有表」，旁挂只是多起了个进程。

测试环境怎么展示跳转（不另开公网）

域名 A 记录只指向网关。测试机没有第二台公网 IP，也不写第二条 A 记录。

客户点击工业 APP 砖块
  → /workbench/ext/{appCode}     工作台壳（登录后，客户只看到这一条路径）
  → 同域 /ext/{appCode}/**       网关入口（演示与生产同一条）
  → TARGET_URL 有值：网关转到该客户 VPC 内网模块机（环境变量 GOOCI_EXT_*_URL）
  → 模块机未启动：提示未跳到
  → TARGET_URL 为空：控制台内置壳
浏览器从不打开模块端口，也不写第二条公网 A 记录。

## 生产环境：控制台怎么知道这家公司加了模块

模块进程自己不上报、不回调。一家客户一套 VPC / 云服务器组，模块只部署在这组内网机上。

厂商作业顺序：

在该客户 VPC 拉起模块进程（此时客户还看不见）

→ 跑只属于它的库表

→ 调 POST /api/ops/apps/implant

enterId / appCode / appName

TARGET_URL = 该客户模块机内网地址（如 http://10.x.x.x:端口）

→ 控制台写 TM_APP_OPEN

→ 客户刷新后工业 APP 出现砖块

→ 浏览器仍只走同域 /ext/{appCode}，由网关转到内网 TARGET_URL


探活是控制台 JVM 去连 TARGET_URL。控制台必须和模块机在同一 VPC（或有内网路由）。可达 ≠ 公网通；未达通常是模块没起来、端口写错、安全组没放行。

运营台改已有模块的隐藏和目标用 `POST /api/ops/apps`，新增才用 implant。

网关只改 HTML 的 src/href、CSS url、以及 JS 里的静态资源根（`/assets/` `/src/` 等）。**不改** JS 里的 `'/'`、路由 path。接口请求靠注入的 fetch 钩子转到 `/ext/{appCode}`。改写过猛会导致模块白屏或按钮失效，不是必然。

`TARGET_URL` 只填客户 VPC 内网。不要把公网 IP、第二条 A 记录或浏览器可达的模块端口写进去。

03 域名备案与客户账号

← 目录

别人家（iSESOL）域名是怎么配的

截图事实：

isesol.com        门户 + 工作台聚合（官网导航和工作台混在一起）
e1.isesol.com     「设备云眼」独立产品站
app.isesol.com    应用商城

点「设备云眼」会离开门户主机名，进子域名。这是 门户 + 产品子域名，不是一台机一个路径。

更像多客户共用的 SaaS 产品集群，不是「一家客户一台机、所有模块挂在同一路径」。

不要学子域名矩阵。

一个域名能解析几个 IP、几台云服务器

  • 一个主机名可以挂很多条 A 记录，协议没有「最多 2 个 IP」。
  • 多 IP ≠ 按客户选机器。 DNS 只会轮询/随便给一个 IP，不认登录账号。
  • 同一名字一般不能既做 CNAME 又做 A。

正确三层：

域名
  → 解析出 1～N 个 IP（用户只看到这层）
      → IP 后面可以是一台云服务器
        或一台入口/负载均衡，后面再挂很多云服务器
用法行不行
一域名 → 一个 IP → 一台机开张可以
一域名 → 多个公网 IP 轮询多台客户机不行，客户会串
一域名 → 一两个入口 IP → 入口再转到很多机正路

域名解析条数不必等于云服务器台数。

公用域名只指向入口；后面机器用内网，不必写进域名。

很多客户，不想每家买域名、备案、服务器

对外卖什么

客户拿到：账号 + 开通了哪些模块。

客户打开：你们已经备案好的 同一个网址。

客户没有：自己的域名、自己的备案、自己的云账号。

你们只做一次：1 个域名、备案 1 次、先买少量云服务器。

https://www.goci.com/工作台
登录 A 厂 → 只看到 A 的数据
登录 B 厂 → 还是这个网址，数据另一套

不能联网：装 EXE，本机打开，连域名都不用。

默认不要「一号一机」

默认隔离靠 账号 + 客户 ID，不靠一人一台机、一人一个域名。

一人一台机只留给：断网本地，或愿意加钱独占的大客户。

子域名（a厂.goci.com）也不当默认，多一层管理。默认就一个网址，靠登录区分。

客户想用自己公司域名访问：那才要客户自己备案，当定制，默认不提供。

04 云服务器拼法

← 目录

会不会要买一台巨大的云服务器

不用。 也不存在好买的「无限大一台」。

客户变多 = 多买几台普通云服务器拼在一起，不是把一台越买越大。

www.goci.com
    ↓
门口（入口，域名只指这里）
    ↓
房间1  8核32G
房间2  8核32G
房间3  16核64G
……以后再加房间

阿里云 / 腾讯云 / 华为云卖的就是 2 核、4 核、8 核、16 核。

先买 1 台普通机就能开张。加机器时客户网址不变。

迷点：每台都有公网，怎么拼进一个域名

每台云服务器都可以有公网 IP，但 不必都写进域名。

域名只认一个门牌号（门口那台的公网）。

请求怎么走：

1. 电脑问：goci.com 是哪个 IP？  答案只有门口 1.1.1.1
2. 请求打到门口
3. 门口按路径内网转发：
     /工作台     → 程序机 192.168.0.20
     数据        → 程序机再问数据库机 192.168.0.30
4. 结果仍从门口回到浏览器

「拼」= 只有门口暴露公网；别的机器走内网，由门口转发。

角色要不要公网写不写进域名
门口要只写它
程序 / 数据库 / 文件最好不要公网，只要内网不写

必须：同一云账号、同一地域、同一个 VPC（专有网络）。

上海一台 + 北京一台，内网拼不上。

去哪买「程序机、数据库机、文件机」

还在你买第一台的那家云控制台买，不是另一种商品、也不是另一家公司。

角色控制台里买什么
门口 / 程序再买一台普通「云服务器」
数据库优先买「云数据库」（比自己开一台装库省事）
文件/图纸买「对象存储」，这是网盘，不是又一台服务器

开张甚至 先别买：一台把程序、库、文件全装完。人多了再拆。

已开了好几台：

  • 同一 VPC：指定一台当门口，其余当程序/库，暂时不用的可关机停费。
  • 不同地域：只能留一个地区来拼。

合并就三步：同一 VPC → 记下内网 IP → 填进门口通讯录。域名一行都不用改。

按已有台数怎么分工

1 台：全放一起，先开张

2 台：门口+程序 / 数据库

3 台：门口 / 程序 / 数据库+文件

4 台+：门口 / 两台程序互备 / 数据库 / 文件或采集

口径：VPC 网络，16 核 32G，50 台设备的工厂，先不分库、不分文件机。

对 50 台设备：核数和内存够用；以后更可能缺的是内存和盘，不是核数。

带宽约 25M 对 50 台设备够用。

盘怎么买

盘建议用途
系统盘80～100G SSD系统、程序。40G 太小
数据盘200G 可以先买（单独挂一块）数据库、设备历史、热附件

系统盘只放系统和程序；数据盘放库和日志；图纸/录像不要堆这两块，走对象存储。

200G 成立的前提：

  • 图纸不大堆在数据盘
  • 没有摄像头录像
  • 采集不要长期存每秒原始波形

用到约七成（约 140G）再扩或加挂。

200G 等于多少数据

真正能用的按约 140G 算（盘不能 100% 堆满）。

存什么大概多少能占满 200G
工单、库存、用户表几百万到上千万条也常常不到几十 G，单靠业务表很难吃满
50 台设备，每分钟一笔状态大约 5～8 年
50 台设备，每 10 秒一笔大约 1～1.5 年
50 台设备，每 1 秒原始点大约 1～2 个月
照片（约 2M/张）约 10 万张
图纸 PDF（约 10M/份）约 2 万份
1 路摄像头录像大约 7～10 天

50 台设备常见用法（几秒到几十秒一个点、热数据留 1 年、图纸不多、无录像），一年大约 50～120G。

200G ≈ 一年的 50 台设备常规监控 + 业务库。

数据盘不能扩容怎么办

不等于整机报废。顺序：

  1. 再挂一块新盘（很多机型不能改大原盘，但允许加挂）
  2. 图纸/备份改放到对象存储，原盘立刻变瘦
  3. 新买更大一块盘，把数据拷过去，改挂载点，旧盘先留几天再卸
  4. 再不行就拆：程序仍在原机，数据库改云数据库/另一台，文件改对象存储；域名仍指门口

同时省着花：日志 15～30 天、原始点位只留短周期、备份不堆同一块数据盘。

拷库换盘时最好有短窗口，避免写到一半。

已经拍板的总图

你们公司
  1 个已备案域名
  1 扇门口（域名只解析到它）
  后面按需加：程序机 / 云数据库 / 对象存储
  全是普通规格，同一 VPC 内网互通

客户
  同一个网址登录
  同一个小程序打开
  账号决定是哪家工厂、开了哪些模块
  不买域名、不备案、不买服务器

模块
  模板复制 → 定制包 → 植入
  路径：/工作台/模块名
  不能停机就旁挂，能停机就并入主后端

本地不能联网
  EXE 启动同一控制台

三句口诀

  1. 全中国客户共用你们一个已备案域名、一个小程序；靠登录分用户。
  2. 域名只指向门口；其它云服务器买在同一家云、同一地区、同一 VPC，走内网。
  3. 模块按需植入，不预装 20 个；50 台设备开张：16 核 32G + 系统盘 100G + 数据盘 200G 可以先上。
